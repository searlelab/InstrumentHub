# Windows 11 deployment

1. Obtain a stable internal DNS name and a lab-issued certificate/key for it. Do not deploy with HTTP fallback.
2. On a connected Windows staging computer, obtain approved WinSW and Caddy executables and run `prepare-offline-bundle.ps1`. It downloads all pinned dependency wheels, builds the application wheel, and packages the source, runbooks, service definitions, and executables.
3. Copy the release bundle, wheelhouse, Caddy, WinSW, certificate, and private key to the Windows host without relying on runtime Internet access.
4. Obtain a lab-provisioned gMSA for the services (or use the built-in `NT AUTHORITY\LocalService` default). Review the hostname and certificate paths in `Caddyfile.example`, then run `install.ps1 -ServiceAccount "LAB\InstrumentHubSvc$"` as an administrator. Add `-DataDirectory "D:\InstrumentHubData"` when the lab requires a non-default instance location; the generated WinSW and initial Caddy configuration use that same location. The installer accepts only LocalSystem, LocalService, NetworkService, or a `DOMAIN\gMSA$` identity, so credentials are never stored in a WinSW XML file.
5. From the installed virtual environment, point the command at the service instance and create the first administrator: `$env:INSTRUMENTHUB_INSTANCE="C:\ProgramData\InstrumentHub"; python -m instrumenthub bootstrap-admin`. Setting the same instance the service uses ensures the administrator is created in the live database rather than an `instance` directory relative to the current path. Then complete setup at the HTTPS hostname.
6. Confirm both Windows services use automatic startup, Uvicorn binds only to loopback with one worker, Caddy serves a trusted certificate, and the daily backup task succeeds.
7. Exercise sign-in, booking, competing browsers, service restart, outage preview, backup, and restore acceptance tests before launch. The Windows-host acceptance pass must also confirm offline startup from the installed bundle, an online backup during concurrent calendar reads and booking writes, and restoration of a copied backup into a disposable instance.

Certificate issuance and renewal remain owned by lab IT. Database/runtime files and logs grant the configured service identity Modify access; certificates and backups grant it read access only so the operational-status page can list them; backups remain writable only by SYSTEM, which runs the backup task, and BUILTIN\Administrators for guarded recovery. All live under the restricted data directory rather than the release directory.
